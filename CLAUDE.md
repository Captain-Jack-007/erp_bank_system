# XB-ERP — правила для Claude Code

Корпоративная ERP-система для АКБ «Народный банк» (Xalq banki). Сейчас — **только frontend** (web + mobile) на mock-данных. Бэкенд (по ТЗ п. 4.3.1 — Java 17+/Spring Boot 3 или .NET 8+, PostgreSQL) появится позже и заменит mock, не трогая экраны.

## Структура

```
packages/shared/src/
  types.ts, i18n.ts, format.ts   ядро: общие типы, словарь, форматирование
  bus.ts                         mock-шина: delay(), emit(), subscribe(), nextNumber(), historyEvent()
  engine.ts                      движок согласований (ROUTES, approvalEngine)
  api/                           API ядра: справочники, согласования, закупки, договоры, заявки
  modules/<id>/                  модуль ТЗ: types.ts, data.ts, api.ts, i18n.ts, index.ts
apps/web/src/
  components/ui.tsx              UI-кит (Card, DataTable, StatusBadge, Modal, BarChart, LineChart…)
  modules.tsx                    реестр модулей: меню, группы, маршруты
  lib/approvalLinks.ts           куда ведёт задача согласования каждого типа
  pages/<id>/index.tsx           экраны модуля, export const routes
apps/mobile/                     Expo (React Native) + expo-router
```

## Главные правила

1. **Данные только через API.** Ядро — `api` из `@xb/shared`; модуль — `<id>Api` (например `warehouseApi`). Экраны никогда не импортируют `data.ts` напрямую. Мутации вызывают `emit()`, экраны обновляются сами через `useApi`.
2. **Модуль живёт в своей папке.** Типы модуля называются с префиксом модуля (`WarehouseItem`, `FtpCurvePoint`), ключи словаря — с префиксом `<id>_`. Связи между модулями (закупки → склад, склад → ОС и т.д.) — только через публичный `<id>Api` другого модуля, никогда через его `data.ts`.
3. **Согласования — только через `approvalEngine`.** Новый тип документа: добавить в `ApprovalEntity` (types.ts) и `ROUTES` (engine.ts), ключ `entity_<тип>` в словарь, ссылку в `lib/approvalLinks.ts`. В модуле: `approvalEngine.register(тип, { onHistory, onFinal })` и `approvalEngine.open({...})` при отправке документа.
4. **Деньги — целые суммы в UZS (`number`), валюта отдельным полем.** Форматирование только через `formatMoney` / `formatMoneyShort`. Расчёты (остатки, амортизация, аллокация, FTP, налоги, консолидация) — кодом из данных, не захардкоженными результатами.
5. **Все тексты интерфейса — через словарь** на трёх языках: `ru`, `uz` (латиница), `en`; узбекская кириллица (`uzc`) генерируется автоматически из `uz`. `defineDict` не даст забыть ключ. Статусы — `<StatusBadge prefix="<id>_status_" status={s} />`.
6. **Web: только компоненты из `components/ui.tsx`, цвета — CSS-переменные из `styles.css`.** Не хватает компонента — добавить в UI-кит.
7. **Mobile: компоненты из `apps/mobile/src/ui.tsx`, цвета из `src/theme.ts`** (значения совпадают с web).
8. **Никаких реальных данных банка, клиентов, паролей и ключей** — ни в коде, ни в mock-данных, ни в запросах к Claude.
9. Не добавлять npm-зависимости без согласования с техлидом (экспертиза кибербезопасности проверяет каждую библиотеку).

Платформенные сервисы (доступ, оргструктура/МВЗ, согласования, уведомления, аудит, экспорт, печать, ЭЦП, интеграции, языки) описаны в [PLATFORM.md](PLATFORM.md) — используйте их, а не собственные реализации.

## Как добавить или расширить модуль

Эталоны: «Закупки» (`pages/procurement`, ядро) и любой модуль из `modules/` (например `warehouse`).

1. `modules/<id>/types.ts` → типы; `data.ts` → демо-данные; `api.ts` → методы на `delay/emit`; `i18n.ts` → `defineDict({ ru, uz })`.
2. `pages/<id>/` → экраны: KPI + реестр с фильтрами (`DataTable`, `FilterBar`), карточка, форма/действие.
3. Новый модуль → запись в `apps/web/src/modules.tsx` (группа меню, иконка, пункт ТЗ) и `export * from './<id>'` в `modules/index.ts`, словарь — в `modules/i18n.ts`.
4. Проверка: `npm run typecheck`, затем пройти сценарий в браузере под разными ролями, на RU и UZ, на ширине 390 px.

## Команды

```
npm install          # из корня репозитория
npm run web          # http://localhost:5173
npm run mobile       # Expo: QR-код для Expo Go / симулятор
npm run typecheck    # все пакеты
```

## Определение готовности

- Работает под ролями из демо-входа (сотрудник, руководитель, закупки, финансы, юрист, бухгалтерия, казначейство, админ).
- Оба языка интерфейса без «сырых» ключей.
- Пустые состояния и загрузка обработаны.
- Вёрстка не ломается на ширине 390 px; широкие таблицы прокручиваются внутри карточки.
- `npm run typecheck` без ошибок.
